## 1. 原始方向与设计理由（历史记录）

**默认左侧主题历史、右侧连续对话；查看依据或记录思考时，再打开右侧辅助面板。**

左侧解决“我讨论过什么、接着聊哪一个”，右侧解决“这次讨论进行到哪里”。墨书的辨识度由三个具体动作体现：**回答能回到原文，不同作者的观点能被分清，用户自己的判断能单独留下来。**

原方案保留第一张的留白、宋体阅读感和小墨角色，取消对米白／棕金的依赖；现已落地炭灰柠黄亮色与石墨蓝暗色。导航使用清楚的无衬线字体，回答仍像文章一样阅读。学习主流聊天工具的历史列表、当前会话高亮和统一输入框，同时把书目范围、原文定位与个人思考放在容易找到的位置。

这轮提供三个方向的独立预览：“纸上书房”“对照研读”“研究札记”。推荐以“纸上书房”为默认界面，把另外两个方向中有价值的辅助面板按需接入。

## 2. 改造前截图暴露的布局问题

| 当前呈现 | 对使用的影响 | 调整方式 |
|---|---|---|
| 历史主题与新主题都放在右上角更多菜单里 | 连续讨论时需要反复找入口，也看不到当前主题在历史中的位置 | 左侧常驻主题列表，顶部放新主题 |
| 标题只显示“主题阅读” | 阅读长回答时容易忘记正在讨论的具体问题 | 顶部显示当前主题标题与书目范围 |
| 回答是一整块很长的正文 | 用户问题、回答、来源状态之间缺少明显层次 | 保留长文排版，增加消息边界、分节标题和回答级来源状态 |
| 来源只有上标及底部“N 个依据”入口 | 能打开来源，但对照时需要离开当前阅读位置 | 上标连接临时来源侧栏，同时保留“在书中打开” |
| 联网是独立地球图标，设置与日常操作混在一起 | 本次回答使用什么范围不够直观 | 把检索范围放到输入区，设置集中到底部入口 |

以上记录改造前截图与旧入口的设计判断，不作为用户行为数据或可用性实验结论；当前实现状态见文首。

## 3. 推荐的信息架构

### 左侧：主题历史

常规桌面宽度约 248–264px，背景比正文略深，列表使用轻量行样式。

从上到下依次放置：墨书标识与收起按钮 → 新主题 → 搜索主题 → 今天／昨天／近 7 天／更早的主题列表 → 我的书库与设置。

每个主题以用户的问题命名，默认取首问的简短标题；不为生成标题额外请求模型。选中项用浅底色、边线和文字强调共同标记。只有当前项、失败项或中断项需要附加状态，普通历史保持简洁。悬停出现行菜单，但键盘聚焦和触屏也必须能打开。

主题历史跨书籍；正文里的“本书对话历史”继续归属于对应书籍。第一版分别命名、分别展示，避免把跨书研究与一句选文的解释混排。未来若做统一搜索，结果必须带“主题／本书对话”的类型标识。

**实现状态：**常驻列表、搜索、日期分组和切换主题已实现；置顶、改名仍为后续能力。删除需要先设计可撤销的回收机制，不作为首版核心入口。

### 右侧：当前主题对话

顶部保留“回到正文”，显示实际主题标题；旁边用“6 本书”或少量书名说明研究范围，点击打开书目选择。右侧最多保留“原文与笔记”“我的札记”等两个相关入口，不再把所有动作塞进更多菜单。

对话区独立滚动。原方案曾建议正文宽度约 740–820px；当前实现改为随窗口扩展的内容区，不再用固定 820px 上限限制宽屏阅读。用户问题用短而浅的气泡或署名区分；小墨回答直接排成文章，不套巨大的回答卡片。回答中的观点关系可用“相近”“互补”“范围不同”等文字说明，只有确实有冲突才强调分歧，不能把每个问题都排成正反辩论。

来源状态跟着对应回答。需要核对时显示“来源待核对”；完成时说明“已核对提供的来源”，不能用认证勾暗示整段答案必然正确。停止、继续生成、重新回答按当前状态出现，不在每条历史消息下重复一排按钮。

### 按需打开：来源与札记

来源面板优先复用现有书名、章节、原文、已有笔记和定位能力。点击上标时打开对应条目，不先让用户浏览一份庞大来源清单。“在书中打开”保留明确的返回讨论路径，并恢复原对话滚动位置。

来源类型明确写为“书中原文”“我的已有笔记”“公开资料”，同时保留文字标识；不能只靠颜色区分。网页资料显示标题与域名，不能伪装成书中原文。来源缺失或书籍已移除时，展示已保存的摘录，并说明暂时无法定位，不能跳到另一处相似原文。

“我的札记”是后续规划的主题级成果区，当前尚未实现编辑器。它让用户记录自己的判断和未解决的问题，保留参考来源。AI 内容加入时必须标成“小墨建议／引用参考”，不会自动转成“我的判断”，也不会自动替换用户写的内容。第一期不必同时实现完整札记编辑器。

### 底部：输入与状态

统一输入框继续承担首问和追问，固定在独立布局区域，正文留足底部空间。输入框下方或内部左下角放本次检索范围，右下角放发送／停止按钮。

范围文案采用“仅本地书籍”与“书籍 + 公开资料”，让用户知道当前选择。**预览展示的是“仅本地书籍”的选中状态，不代表会把现有联网默认值静默改掉。**是否记忆为主题级偏好，需要作为新增行为实现。

正常时仅显示小号“已保存在本机”；保存失败时显示可操作的“未保存 · 重新保存”。检索、生成、来源核对和本地保存保持独立状态，重新保存绝不能再次请求模型。

## 5. 墨书应该有的五个辨识点

1. **问题即目录。** 历史呈现一段段阅读中的追问，能看见它们依赖哪些书，而不只有“聊天 1、聊天 2”。
2. **引用可以走回去。** 上标 → 具体原文 → 原书位置 → 返回同一条讨论，路径完整且可恢复。
3. **作者、小墨、我，各自有署名。** 原文是材料，AI 回答是分析，个人札记是用户的判断；三者可以关联，但归属不混淆。
4. **比较有依据。** 面对同一个问题，指出作者各自回答的范围及依据；不强制制造“观点冲突”，也不凭空补齐作者没说过的话。
5. **成果留在自己的书房。** 历史、原文锚点、笔记和札记都在本机，断网仍能阅读与查看；模型和公开资料请求只在用户使用对应功能时发生。

小墨形象只在空白主题、首次引导和回答署名旁轻量出现。正文讨论中保持安静，避免大幅角色插画占据阅读空间。界面称呼统一“小墨”，不混用“小墨”“墨点”“AI 助手”等多套名称。

## 6. 三种预览如何取舍

| 方向 | 核心布局 | 适合场景 | 取舍 |
|---|---|---|---|
| 纸上书房（推荐） | 常驻历史 + 宽松对话；原文以局部入口出现 | 日常连续阅读与讨论 | 熟悉、安静；需要查看大量依据时再展开面板 |
| 对照研读 | 历史 + 对话 + 当前引用来源面板 | 追问依据、比较作者、核查引用 | 依据更近；对窗口宽度要求更高，来源面板需可关闭 |
| 研究札记 | 历史 + 对话 + 用户写作侧页 | 讨论后整理自己的理解 | 更有阅读成果感；需要新增主题札记能力，不宜一次堆进首版 |

这三个预览是结构探索。推荐落地一套统一界面：默认用纸上书房，引用和札记按需打开；不要做成三个需要用户反复切换的产品模式。

预览图为静态生成概念图，示例书摘、对话及札记不构成真实模型结果或事实核验。若图像文字与本方案在细节上有出入，以交互规则和后续实现验收为准。

## 7. 必须提前设计的状态

| 情境 | 行为要求 |
|---|---|
| 空白新主题 | 简短引导、书目范围及统一输入框；不把未发送空白主题写成一堆历史记录 |
| 正在生成时选择另一主题 | 首版不暗示多主题后台并行；提供“停止并切换”，先保存部分回答，再切换 |
| 保存失败 | 留在当前主题，明确提供重新保存；不得静默切换导致内容丢失 |
| 恢复旧主题 | 恢复该主题自己的书目、来源和消息状态；重试沿用对应问题的范围 |
| 改变研究书目 | 对后续问题生效，旧回答保留当时的来源；必要时用时间分隔说明范围已调整 |
| 输入框已有未发送文字 | 按主题保留本地草稿；跨主题切换不把草稿带到另一个主题 |
| 向上读旧消息时继续生成 | 保持当前位置，用“有新内容”入口返回底部，不强制抢走滚动位置 |
| 未连接模型 | 仍可查看历史、原文和笔记；发送位置提示去配置连接，不用整屏拦截 |
| 原文书籍被移除 | 保留引用摘录和笔记，说明原书暂不可用，不丢弃历史记录 |

本表保留原始状态设计要求。主题切换和本地保存保护已有实现；按主题保存草稿等后续交互仍需单独实施与验收，不能由布局完成推断为全部交付。

## 8. 视觉、窗口与键盘规则

**颜色（已实施）**：炭灰柠黄亮色使用白色正文面 `#FFFFFF`、炭灰历史栏 `#252628`、正文 `#252629` 和柠黄标记 `#D9EB69`；白底链接使用深橄榄色 `#4F5E13`。石墨蓝暗色使用正文面 `#1C2028`、历史栏 `#14171D`、正文 `#E6EAF0` 和浅蓝强调 `#A4BDF4`。亮／暗／跟随系统复用现有本地设置。原暖纸赭色方案仅保留在旧概念图中，不再是主题工作区的当前规范。

**字体**：导航与控件使用系统中文无衬线；长文与标题可沿用宋体。正文建议 18–20px、行高 1.75–1.9，导航 14–16px，次要说明尽量不低于 12px。控制中文每行约 35–45 字，支持用户调整，不因增加侧栏而压缩字号。

**层级**：通过留白、标题、分隔线组织界面；不把每条历史、每段回答、每个来源都包成卡片。输入框约 12px 圆角，按钮与小控件约 6–8px；阴影只用于真正覆盖在内容上方的浮层。

| 窗口宽度 | 布局规则 |
|---|---|
| ≥1440px | 历史常驻；来源／札记可临时并排，保证对话正文至少约 680px |
| 1100–1439px | 历史常驻且可收起；辅助面板优先浮层，不硬塞三栏 |
| 768–1099px | 历史改为可打开抽屉；默认保留完整对话宽度 |
| <768px | 顶部“主题”入口打开历史；来源／札记用独立抽屉，避免同时展开；输入区不遮正文 |

图标使用统一线性风格，并有可读名称。触控目标优先 44px；键盘可从历史进入对话、引用、输入框。Escape 只关闭最上层面板并返回触发点，包含 macOS WebKit 鼠标点击不自动聚焦的情况。Enter／Shift+Enter 保留现有行为，中文输入法确认候选字不能触发发送。新增快捷键需要检查与阅读引擎现有绑定的冲突。

纸张主题、深色主题和墨水屏都需要覆盖；状态不能只靠颜色，焦点不能只靠阴影。图片展示浅色方向，不意味着取消现有阅读外观能力。

## 9. 分期落地与本地数据约定

### 第一阶段：把常用路径整理清楚（主要布局与入口已实现）

实现左栏历史、新主题、搜索与分组；右侧实际主题标题、书目范围、统一输入区；把现有来源弹窗改为可关闭的侧栏；重新安置设置和联网范围。保留原文回跳、本地保存、流式检查点、停止／重试、损坏恢复与备份。

当前列表与主题切换按稳定会话标识关联，保留原有本地记录与保存保护。后续扩展仍须保持主题身份与来源对应，不按标题去重；涉及格式变化时补充兼容与迁移验证。

### 第二阶段：补足长期使用的整理能力

增加改名、置顶、主题草稿、未解决问题入口，以及跨书返回主题时的位置恢复。先把这些本地操作做可靠，再考虑更复杂的标签和统一搜索。

### 第三阶段：形成自己的阅读成果

加入主题札记、引文引用、讨论回链和 Markdown 导出。用户写作与小墨建议分开存储；未来可按需增加观点对照视图，不能把完整五步方法重新变成强制向导。

**本地存储约定保持不变。** 单书笔记与对话继续在 `Books/<bookHash>/`；跨书主题通过 `AppService` 的 `Data` 基目录保存，macOS 默认实际文件是 `~/Library/Application Support/local.activereader.desktop/Readest/thematic-research.json`。新增置顶、草稿和札记也在本机。格式扩展必须同时更新验证、备份清单、恢复合并及迁移测试，沿用安全替换和有效副本恢复，不引入账号或云数据库作为前提。

## 10. 实现验收标准

- 从左侧一次点击即可恢复历史主题，并明确看到当前项和书目范围；同名主题不会相互覆盖。
- 点击引用能看到对应原文，再进入正确书中位置，返回时仍是同一主题与同一段讨论。
- 保存失败、回答中断、联网关闭均有明确状态；“重新保存”不调用模型。
- 新主题、切换历史、返回正文都保留未完成回答与草稿，不发生串话。
- AI 分析、书中原文、用户写作在视觉和数据归属上均可区分。
- 在 1440、1280、1024、768、390px 下没有挤压、遮挡与横向溢出；支持高倍缩放。
- 通过键盘焦点、中文输入法、窄窗、重启恢复、离线查看及真实本地文件备份回归。
