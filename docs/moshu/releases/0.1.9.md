## 本次结果

原报告 F01–F11 已完成对应修复，桌面版 **0.1.9 已安装到 macOS 应用程序目录中的 `Active Reader.app`**。修复围绕本地数据、对话恢复、来源核对和当前产品回归展开。报告中的产品机会（连接向导、书库聚合入口、个人总结编辑等）仍属于后续功能建议，没有混入这次可靠性修改；千本规模索引的内存占用仍有后续优化空间，详见基线。

## 数据放在哪里

桌面根目录：`~/Library/Application Support/local.activereader.desktop/Readest`

| 内容 | 位置 |
|---|---|
| 书籍文件、原生划线和批注 | `Books/<bookHash>/` 下书籍及 `config.json` |
| 笔记、疑问、原文位置、修订 | `Books/<bookHash>/reading-method.json` |
| 阅读模式、章节思考 | `Books/<bookHash>/reading-modes.json` |
| 普通对话、原选文/CFI、消息状态与来源 | `Books/<bookHash>/reading-dialogues.json` |
| 跨书主题与主题历史 | `thematic-research.json` |
| 上一有效记录 | 对应 JSON 的 `.backup` |
| 恢复前快照及合并分歧 | `restore-snapshots/` |

以上是桌面实际路径；代码中的 `Data` 是 `AppService` 基目录标识，默认映射至 `Readest/`，不是其下额外一层文件夹。网页预览使用当前浏览器的 IndexedDB，与桌面书库独立。未增加 Supabase、账号同步或云端历史存储。桌面 Key 沿用系统安全存储；网页预览 Key 沿用会话内存。

使用方式：正文“呼叫小墨”内打开“本书对话历史”；主题菜单内打开“历史主题”。出现本地写入失败时使用独立保存重试。书库备份窗口可撤销最近一次恢复、导出合并前双方内容。

### 检索性能基线

环境：Apple M5 / macOS arm64 / Node 24.19.0，Vitest jsdom、真实 EPUB 解析、内存 AppService。每本合成书 100 段 × 215 字，压缩后约 1.8 KB，内容高度可压缩；所有书都命中查询，热缓存复用不可变 File。此表不含模型、网络、原生磁盘或 WebKit。

| 书籍数 | 冷索引 | 热索引 | 5 次检索范围 | 取消到调用返回 | 最大事件循环间隔 |
|---|---:|---:|---:|---:|---:|
| 10 | 295 ms | 13 ms | 4–6 ms | 0.33 ms | 17 ms |
| 100 | 2.12 s | 134 ms | 35–51 ms | 0.16 ms | 16 ms |
| 1000 | 23.54 s | 1.64 s | 410–486 ms | 0.22 ms | 27 ms |

1000 本合成基线的进程峰值 RSS 约 2.44 GB。当前已改善取消和主线程响应，但仍全量持有段落；取消到调用返回不等于所有底层 I/O 已结束，不可取消的 I/O 完成后仍会释放资源。原生可变文件为避免漏掉“同大小、恢复 mtime”的替换仍完整校验内容；后续可在真实大书库数据支持下选择 Worker 或本地数据库索引。本次数据不是桌面性能承诺，也不把一次冷/热运行写成 p95。

在 `apps/readest-app` 目录复跑：`node scripts/benchmark-thematic-retrieval.mjs`。详细数据在 `apps/readest-app/bench/thematic-baseline.json`。
