# AI 阅读器产品设计与开发计划

> 2026-09-20 的历史开发计划。部分流程已被后续版本替代；原文“尚未构建”等描述仅针对当时阶段。当前状态见[资料索引](../README.md)。

更新：2026 年 9 月 20 日。电脑端优先，接受开源，优先快速做出可用版本；暂按 macOS 首发安排。本版恢复鼠标视觉跟随的 MVP 地位，并把《如何阅读一本书》融入完整阅读过程。

**产品目标：帮助用户顺畅地读下去，理解作者，再形成并留下自己的判断。** 基于 Readest 二次开发；首版完整支持常见 EPUB 的核心流程，PDF 先继承基础阅读能力。

## 1 整体设计：阅读方法如何变成功能

《如何阅读一本书》的基础、检视、分析、主题阅读提供方法骨架。这些能力可按需要使用，无须逐关解锁。首版重点服务非虚构书的理解阅读；轻松阅读仍可只打开书。[出版社介绍](https://www.simonandschuster.com/books/How-to-Read-a-Book/Mortimer-J-Adler/9781476790152)

| 设计板块 | MVP 做到什么 | 后续开发什么 |
| --- | --- | --- |
| **舒适阅读与鼠标视觉跟随** | 继承基础阅读；增加无需按住鼠标的行跟随，当前行突出、周围行清晰、远处轻淡；可关闭 | 复杂分栏、竖排、PDF 的精细适配，段落跟随 |
| **认识这本书：系统略读** | 在目录旁提供序言、目录、章节开头等浏览入口；记录阅读目标、体裁和一句初步判断 | 辅助整理全书结构，比较初读与读完后的理解变化 |
| **先读下去：粗读与问题暂存** | 遇到困难可立即问，也可保存原文位置与一句疑问后继续；问题可解决、保留或放弃 | 联系后文解释，重读时找回相关疑问 |
| **分析作者：概念、观点与理由** | 选文后可问“什么意思”“为什么这样说”“依据在哪”；答案关联实际原文 | 跨章节论证、隐含前提、反例、概念关系，按需画论证图 |
| **我的理解与判断** | 可写“我理解的是”“我是否赞同及理由”；AI 先核对有没有误解作者，再讨论异议；保留原稿 | 分别检查事实、证据、推理与前提；外部事实核验 |
| **阅读四问与个人关联** | 每本书一张可分次填写的阅读卡：整体内容、具体论述、我的判断、对我的意义；全部可跳过 | 观点变化、应用记录、与已有笔记的关联 |
| **回忆、回顾与笔记** | 主动点“回顾”后可先写一句回忆，再看原文；原文、我的话、AI 建议分开保存和导出 | 对用户选中的内容安排间隔回顾，支持跳过和调整频率 |
| **围绕问题跨书阅读** | 首版保留书名、版本、位置等来源信息，为后续使用准备 | 先确定共同问题，再比较不同书的概念、观点和证据，形成自己的综合判断 |

检视阅读包括系统略读与粗读，不能只做一份 AI 摘要。分析阅读从理解作者开始，再进入评价；主题阅读以用户的问题组织材料。

SQ3R 用于“浏览—提问—阅读—复述—回顾”的可选提示；检索练习、间隔回顾和自我解释是补充方法。鼠标交互与来源分栏属于本产品的改编设计，不能全部归为书中方法，也不能据此承诺学习效果。

## 2 鼠标视觉跟随：明确列入 MVP

**首版效果：鼠标或触控板指针停在哪一行，哪一行就成为视觉重点。** 当前行使用浅色背景，上下各约两行保持正常清晰度，其余区域轻微降低明暗对比；范围与强度可调。文字仍可阅读、选择和复制。

| 操作或状态 | 对应行为 |
| --- | --- |
| 开启“视觉跟随”，指针在正文内移动 | 无需按住鼠标；根据真实文字行定位，空白区域不乱跳 |
| 指针停住 | 引导停在原处；不自动翻页、催促或判断走神 |
| 拖选文字、打开菜单或移到 AI 侧栏 | 暂停跟随并恢复全文正常显示；完成后再次移动到正文才恢复 |
| 翻页、滚动、调整字号或窗口大小 | 更新可见文字行的位置，避免高亮错行；找不到正文时暂时恢复正常显示 |
| 关闭或不使用鼠标 | 一键恢复普通阅读；保留基座标尺的键盘操作，遵循系统“减少动态效果”设置 |

默认关闭，工具栏提供清楚的开关并记住用户选择。首版验收横排、单栏、可重排 EPUB；其他布局保留原有阅读方式，验证通过后再开放跟随。

**复用与新增的边界：** Readest 已有阅读标尺、行框计算及遮罩，但其指针移动处理依赖拖动状态。可复用这些底层能力，仍需新增自由悬停跟随、交互暂停和弱化强度控制，不能把“已有标尺”当成这项需求已完成。[固定版本源码](https://github.com/readest/readest/blob/v0.12.8/apps/readest-app/src/app/reader/components/ReadingRuler.tsx)

这项功能首先验证舒适度、找回阅读位置和操作干扰，不用鼠标轨迹推断专注，不以无损提速作为验收目标。

## 3 四问如何贯穿界面

阅读卡围绕四个问题组织：**全书讲什么 → 作者具体怎样说 → 我认为是否成立 → 这对我有什么意义。** 最后一问可以是认知变化、生活经验、未解问题或可尝试的行动。[Adler 对四问的说明](https://thegreatideas.org/wp-content/uploads/2022/01/TGIO848.pdf)

沿用阅读器主界面，增加少量入口，无须为每种方法开发独立页面：

- **目录旁“认识这本书”**：浏览结构，填阅读目标和初步判断。信息缺失时允许跳过，AI 仅在请求时补充，并标明看过哪些内容。
- **正文工具栏与选文菜单**：视觉跟随开关；选文后提供“问这段”“存疑问”“写理解”。概念、理由、依据等放进“问这段”的快捷提问中。
- **右侧阅读助手**：容纳问答、疑问列表与四问阅读卡。相关片段可回原文；每次关闭都能接着读。
- **结束一次阅读时**：用户主动选择回顾，可更新阅读卡、写一句回忆或个人关联；不弹出必填作业。

例如，读到一个主张时，可以先暂存问题；读完小节再写自己的理解，要求 AI 对照依据，随后补充赞同或异议，最后存入阅读卡。普通问答始终可以直接使用。

体裁与阅读目标允许手动修正：首版提供少量提示模板，哲学关注概念与前提，历史关注材料与解释，社科关注数据与推论，实用书关注适用条件；小说关注人物、语言与解释依据，不套用论证评分。小说默认限当前片段与必要邻文，跨章节内容由用户明确选择；“防剧透”须通过实际测试。

## 4 直接复用什么，自己开发什么

**主选 Readest，Koodo Reader 备用。** 候选起点为 Readest [v0.12.8](https://github.com/readest/readest/releases/tag/v0.12.8)，构建和试读通过后锁定版本；沿用 TypeScript、React、Tauri 及现有存储。用户接受开源，按项目 AGPL 许可维护修改版。[项目说明](https://github.com/readest/readest) · [许可证](https://github.com/readest/readest/blob/v0.12.8/LICENSE)

| 能力 | 开发方式 |
| --- | --- |
| 书架、导入、目录、搜索、排版、主题、进度、朗读 | 继承已有能力，修复实际遇到的问题 |
| 划线、选文定位、基础笔记、本地存储与导出 | 复用，补充疑问、理解、判断及来源字段 |
| 模型连接、流式回答、聊天界面与历史 | 复用，接用户自己的服务地址与 Key |
| 阅读标尺与行位置计算 | 复用底层，补鼠标悬停跟随及暂停逻辑 |
| 读前入口、四问阅读卡、理解核对、来源区分 | 自己开发，集中在目录、选文和侧栏中 |
| 全书索引和检索 | 保留现有模块，后续按需启用；首问无需先索引整本书 |

已有 AI 不等于已接通我们的流程：选文直达、上下文范围和引用保存仍需改造。固定版本已有自定义模型连接；实验性检索的引用不能假定重启后仍可用。[模型连接](https://github.com/readest/readest/blob/v0.12.8/apps/readest-app/src/services/ai/providers/OpenRouterProvider.ts) · [现有来源存储](https://github.com/readest/readest/blob/v0.12.8/apps/readest-app/src/services/ai/adapters/reedySourceStore.ts)

## 5 整体如何开发

新增代码集中为四部分，尽量少改阅读内核：

1. **视觉跟随控制器**：复用可见行的位置，控制高亮与暂停；鼠标移动在本地处理，不调用 AI，不逐次扫描全书。
2. **阅读上下文连接**：取得书籍、章节、选文、邻文和位置；默认处理当前范围，超出范围时明确提示或按用户选择扩展。回答找不到原文支持时标为推测或不足。
3. **阅读方法侧栏**：读前资料、疑问、理解与四问共用笔记和聊天组件；AI 反馈供用户判断，不自动改写个人结论，不给未经验证的理解分数。
4. **记录与模型适配**：保存书籍版本、原文快照、位置、用户原稿与修改、AI 反馈、模型和时间；复用本地存储与模型通道，Key 不进入源码或导出文件。

首版本地书库、自带 Key，不新增账号或云后端。关闭官方账号、订阅与同步入口，检查默认远程请求，关闭上游自动更新以免覆盖修改版。基础阅读与已保存记录应离线可用；AI 失败不阻断阅读。数据扩展要能迁移，上游更新单独合入。

## 6 开发顺序与后续版本

**改按 AI 编程的一天冲刺组织，目标是交付可实际阅读的完整 MVP。** 原先的 4–6 周估算缺少实际构建依据，撤回；不再逐项估算人工天数。一天是冲刺目标，完成以运行结果与验收为准。执行清单见 TODO（本机验证资料，未上传）。

| 顺序 | 执行方式 | 可检查的交付物 |
| --- | --- | --- |
| 1. 基座与共享接口 | 先完成 | 本地构建、导入、选文、模型调用跑通；确定共享数据及模块边界 |
| 2. 三个功能模块 | 接口确定后并行 | A 鼠标视觉跟随；B 读前、四问、理解与回顾；C 选文 AI、引用与疑问 |
| 3. 集成与记录 | 主 Agent 汇总 | 统一入口，持久化原文与个人内容，来源清楚的 Markdown 导出 |
| 4. 实际阅读与打包 | 集成后完成 | 阅读闭环通过，重启保留记录，提供可运行的 macOS 试用包；遗留问题有记录 |

首轮用约 5 本代表性 EPUB 检查中文选文、长章节、脚注、图片、翻页、滚动、字号及主题变化。关键验收是视觉引导不妨碍阅读、引用不串书、记录不丢、个人原稿不被覆盖；用故意误解原文的例子检验 AI 是否能指出问题。对视觉跟随和理解核对分别收集反馈。

PDF 基础阅读继承上游；PDF 选文问答、定位和视觉跟随分别验收，通过后再标为支持。扫描件 OCR、复杂图表理解不进入首版。

| 后续阶段 | 主要开发内容 |
| --- | --- |
| v0.2 深化单书阅读 | 联系已读章节、论证与反例、理解变化；优先补真实使用中的 PDF 或布局问题 |
| v0.3 回顾与迁移 | 用户选择内容后的间隔回顾、关联笔记、应用记录 |
| v0.4 主题阅读 | 共同问题、术语比较、观点分歧与证据；外部事实核验单独标注来源和日期 |
| 对外使用 | Windows 验证；再按需求加入同步、移动端、统一 AI 服务与用量管理 |

首版保留关键阅读动作的最小实现；自动全书分析、复杂图谱和跨书研究后置。第一项开发工作仍是跑通 Readest，并验证“鼠标引导阅读 → 选文 → 写理解 → 对照原文 → 保存”的链路。若基座存在明显障碍，再用同一标准检查 [Koodo Reader](https://github.com/koodo-reader/koodo-reader)，不并行维护两个 fork。

本计划依据原始文档、方法资料与固定版本源码检查制定；尚未构建应用、实际试读或验证效果。
