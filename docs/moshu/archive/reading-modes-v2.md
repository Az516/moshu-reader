# 墨书：阅读模式产品设计 v2

> 历史设计方案。五阶段主题向导、自动全书地图及部分整理能力不代表当前实现；0.1.10 使用常驻历史与连续主题对话。旧角色名称“墨点”保留作历史记录，当前称“小墨”。设计示例不是用户数据。

这版从阅读目的出发，不沿用传统阅读器的侧栏和标签页结构。用户导入书籍后先选择阅读模式；模式决定系统如何导航、何时提醒、如何记录，以及墨点提出什么问题。三种模式可以随时切换，原文标记、疑问和个人思考始终属于同一本书，不因模式变化而复制或丢失。

## 产品结构

基础阅读不是需要选择的模式。字典、翻译、朗读、字体和无障碍能力属于所有模式的底层能力。

用户真正选择三种目的：

- **快速阅读**：先建立全书地图，再决定是否精读以及精读哪里。
- **分析阅读**：重构作者的问题、关键词、命题和论证，理解后再批评。
- **主题阅读**：围绕用户提出的问题，同时比较多本书并形成自己的判断。

模式选择不是一次性设置。快速阅读留下的疑问可以带入分析阅读；分析阅读中的命题可以加入主题阅读；主题阅读里的任何观点都可以跳回原书。

## 墨点：陪读角色

墨点角色（本机验证资料，未上传）

墨点代替界面中的“AI”称呼。它是纸张与墨迹组成的安静陪读角色，负责提醒、追问、查证和整理来源，不代替用户下结论。

墨点遵守四条行为规则：

1. 阅读顺畅时保持安静，只在页边显示很小的状态。
2. 每次只提出一个和当前情境有关的问题。
3. 回答明确区分书中原文、公开资料和墨点推断。
4. 先要求用户表达，再检查遗漏和误读，不直接生成“标准读后感”。

## 快速阅读

快速阅读（本机验证资料，未上传）

进入模式后，系统依次扫描书名、目录、序言、章节首尾和抽样页面，生成一条简洁的“全书地图”。它不是摘要，而是帮助用户回答：这是什么书、作者试图解决什么问题、哪些部分值得深入。

正文默认启用“字句跟随”。鼠标附近 5–9 个字轻微放大和加重，邻近文字保持稳定，避免整行遮罩造成机械扫读。

当指针在同一句停留超过 5 秒，同时没有滚动、键盘输入或文本选择时，墨点从页边探出并给出三个动作：

- **标个疑问**：留下醒目的问号，继续阅读。
- **解释一句**：只根据当前原文和邻文做一句简短解释。
- **继续往下**：收起提示，并在 60 秒内不再打扰。

提醒每章最多主动出现三次，并提供“今天不再提醒”。五秒不是判定用户“没看懂”，只是一次低打扰的帮助机会。

章末只问一个问题：“作者这一章正在解决什么问题？”快速阅读结束时，系统让用户选择精读范围，而不是要求完成完整总结。

## 分析阅读

分析阅读（本机验证资料，未上传）

分析阅读开始时，系统先根据书籍类型建立空的论证骨架：作者的问题、核心概念、主要命题、理由与证据、本章在全书中的位置。内容由阅读过程逐渐填充，不提前生成看似完整的结论。

正文只保留一个自有动作“对话”。用户可以自由写理解、疑问、判断或反驳，无需先选择笔记类别；系统在后台识别它更接近概念、命题、证据还是问题。

“先存疑”会在原文页边钉一个醒目的 `?`。未解决时保持琥珀色，后文提供答案时提示可能相关，用户确认后变为较小的勾选标记。疑问不会弹窗阻断阅读。

“请墨点查证”有两种范围：

- 关闭公开资料：只分析原文和相邻段落。
- 打开公开资料：实时检索资料，并把书中原文、公开资料、墨点推断分区展示，每条信息带来源。

墨点先检查用户是否准确复述作者。只有基本理解成立后，才继续追问信息是否不足、事实是否错误、推理是否成立、分析是否完整。这把“理解后再批评”的阅读纪律做进交互流程。

到章节末尾才出现重构入口，要求用户完成：作者的问题 → 核心命题 → 论证链 → 本章在全书中的位置。它不会常驻正文。

## 主题阅读

主题阅读（本机验证资料，未上传）

主题阅读从用户的问题开始，例如“一个人为什么会拖延？”。它按《如何阅读一本书》的方法形成五个递进阶段。阶段属于整个研究过程，每个页面只显示当前任务，不把它们变成正文里的笔记分类。

1. **定义问题**：用户写出主问题、研究范围和暂不讨论的内容，再拆成一组能同样询问所有作者的共同问题。
2. **检视书目**：墨点扫描书库并推荐候选书籍，用户确认研究范围；随后只检视与问题有关的章节和段落，不要求先读完整本书。
3. **统一术语**：用户建立本次研究采用的中立术语，系统把各作者的原词映射到这些术语，同时保留原词并提醒可能存在的错误等同。
4. **整理观点**：围绕同一个共同问题，先忠实列出每位作者的回答、理由和原文依据，不预设作者之间存在分歧。
5. **分析与综合**：用户确认观点后，墨点再分析观点之间是相近、互补、讨论范围不同、确实冲突，还是没有直接回答。用户可以继续追问、纠正关系，最后形成自己的判断。

每本书在研究书目中显示真正相关的原文数量，而不是笼统的相关度。每条作者观点都必须链接到具体书籍、章节和原文；没有回答也要明确显示，不能由系统替作者补齐观点。

分析页面按照“原始观点 → 观点关系 → 墨点的客观分析 → 用户追问与纠正”展开。只有确实存在冲突时才进入“核心争议”；观点互补时则重点说明各自解释的层次与范围。任何跨书结论都保留来源链，公开资料与书中内容分开标注。最终可导出问题范围、研究书目、中立术语表、观点清单、关系分析、综合判断和引用目录。

### 主题阅读的单屏原则

五个阶段按顺序进入，每个屏幕只完成一个任务。当前处于“整理观点”时，只展示一个共同问题、各作者的一句话回答、依据摘要和一个下一步动作。

- 研究书目收成“4 本书 · 32 处原文”的摘要入口，点击后用临时浮层查看。
- 中立术语收成“8 个术语 · 1 项待确认”的摘要入口，当前屏不展开术语表。
- 每位作者只保留一句核心观点、理由摘要和原文数量；具体引用按“查看原文”打开。
- 当前屏不显示关系分类。用户确认观点以后，再进入墨点的关系分析与交流屏。
- 墨点一次只提出一个问题，不常驻大型对话框。

这种渐进展示保证方法完整，同时避免把书目、术语、争议、引用和写作同时堆在一张屏幕上。

### 综合讨论

综合讨论：核心争议（本机验证资料，未上传）

进入分析与综合后继续采用一屏一任务，并依次完成三个小步骤：

1. **观点关系**：墨点分析观点是相近、互补、范围不同、确实冲突，还是作者没有直接回答；用户可以追问和修正。
2. **客观讨论**：用中立语言呈现各方答案、依据与适用范围。只有存在冲突时才突出核心争议；引用用脚注嵌在段落中，点击才展开原文。
3. **我的判断**：用户最后写自己的结论、采用的依据、结论的适用范围和仍未解决的问题，并回答“这和我有什么关系”。

写作屏以一张宽大的正文稿纸为主体，不显示书目栏、术语表或完整引用列表。墨点以页边编辑批注的形式工作，每次只指出一个术语偷换、遗漏立场、推理跳跃或证据缺口。用户可以接受提醒或查看依据，墨点不直接改写整篇文章。

## 共同交互规则

- 所有仅有图标的按钮，悬停约 400ms 后显示名称、用途和快捷键。
- 墨点的提示可以单次关闭、当天关闭或永久关闭；停留提醒单独设置。
- 字句跟随在快速阅读默认开启，在分析阅读默认关闭，用户可以随时切换。
- 自由输入优先，结构化整理在保存后进行，避免用户在阅读时不断分类。
- 任何自动生成的书籍结构、命题或主题关系都标记为“待确认”，用户确认后才进入长期知识库。
- 所有模式都支持一键回到引用原文，并保存书籍版本和章节位置。

## 开发顺序

第一阶段先完成模式选择、快速阅读地图、字句跟随、5 秒停留提醒、墨点角色、分析阅读问号标记和单一对话入口。这些构成完整可用的阅读闭环。

第二阶段加入章节论证重构、公开资料查证、来源分区和从疑问到解决的关联。

第三阶段实现主题研究问题、书库相关性推荐、概念对齐、跨书观点清单、关系分析、可追问的墨点讨论和综合判断。主题阅读依赖前两个阶段积累的可靠原文锚点，不应作为第一天的伪演示功能强行上线。
