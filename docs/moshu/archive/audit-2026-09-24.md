## 1. 结论与优先顺序

**软件已有清晰的产品方向和可用的阅读基础。下一阶段最值得投入的是数据可靠性、AI 对话的异常恢复，以及与当前产品一致的发布验证。** 三种阅读模式、围绕原文的提问、疑问记录和多书主题讨论已经形成了差异化，不需要立即增加更多阅读模式。

本次整理出 **11 组问题：4 组 P1、7 组 P2**。其中，数据问题进行了合成数据复现，按钮重叠在桌面端实测确认，其余均标明代码证据及未验证的部分。没有发现足以定为 P0 的现象，也没有证据表明用户现有数据已经损坏。

建议按以下顺序推进：

1. **先保证成果不丢失**：补齐主题历史备份、恢复合并、损坏回退和保存失败重试。
2. **再保证对话不中途失去上下文**：修复重试跨主题、无书籍时重建主题、部分回答混入正常历史。
3. **同步修复发布门禁和明显交互问题**：更新失效 e2e，解决按钮重叠、弹窗焦点和停止检索的响应。
4. **最后扩展阅读成果的利用方式**：围绕待解决疑问、主题研究和个人判断形成更顺畅的复习与导出流程。

优先级含义：P1＝建议下一次正式更新前解决；P2＝后续迭代完善，影响特定流程或使用规模。严重程度与证据强度分开判断。

## 3. 已有能力值得保留

- **阅读入口简洁**：快速阅读、分析阅读、主题阅读各有一句解释；当前桌面尺寸下模式选择页布局完整。书库空状态直接引导导入，没有多余步骤。
- **读书与思考结合**：原文位置、疑问标记、章节思考和主题引用不是完全独立的数据；已有回到书中核对的设计与实现。
- **AI 基础交互较完整**：主题流式输出、停止、重试、继续生成、中文输入法发送保护、来源检查失败提示已有实现，不能视为全部缺失。
- **有本地优先基础**：单书数据修改有串行队列，读取有版本与书籍身份校验；桌面 Key 使用系统安全存储，网页 Key 为会话内存；读取 Key 有超时和取消处理。
- **阅读成果已有出口**：阅读记录 Markdown 导出已包含原文、书籍版本、修订和模型建议。后续应完善其组织和恢复能力，避免另做一套平行数据体系。

### F01｜主题历史不在备份内

**触发与影响**：创建主题讨论后执行现有书库备份，再恢复到空数据目录，主题历史没有对应备份条目可恢复。书籍还在不等于主题讨论也在。

**证据**：[主题存储位置](../../../apps/readest-app/src/features/reading-modes/thematic.ts) 为 `Data/thematic-research.json`；[ZIP 收集函数](../../../apps/readest-app/src/services/backupService.ts) 收集书库、设置和 `Books` 下文件，不读取该主题文件。合成服务执行实际收集函数确认了这一点。

**方案**：定义带版本的墨书备份清单，显式列出主题历史、阅读记录和模式数据；区分用户成果与可重建索引。旧 ZIP 继续可导入。

**验收**：含多主题、多轮消息和原文引用的备份，恢复到全新书库后，记录数量、正文与定位信息一致。

### F02｜恢复旧备份会覆盖新记录

**触发与影响**：备份后新增阅读记录，再恢复旧备份。恢复逻辑只对 `config.json` 合并，`reading-method.json`、`reading-modes.json` 会直接写入旧内容。合成复现中，两条记录变回一条，新的章节思考变为空。

**证据**：[恢复分支](../../../apps/readest-app/src/services/backupService.ts) 与 [恢复界面“合并当前书库”的说明](../../../apps/readest-app/src/app/library/components/BackupWindow.tsx) 存在能力边界偏差。这不表示上游所有数据都不合并，问题集中在新增定制文件。

**方案**：阅读记录按稳定 ID 合并，结合修订与更新时间处理同一记录；章节思考冲突保留两个版本或明确让用户选择。恢复前自动留下可撤销快照。

**验收**：旧备份恢复不能静默删除新记录；同一记录两端各自修改时能够识别冲突；重复恢复不重复添加；恢复操作可撤销。

### F03｜有备份文件，但没有完整故障恢复能力

**触发与影响**：主 JSON 截断或格式损坏时，即使 `.backup` 有效，加载仍报错。主题历史保存在单一主文件，连续保存不产生备份；一次写入中断存在影响全部主题的风险，尚未做真实断电实验。

**证据**：[阅读记录加载](../../../apps/readest-app/src/features/active-reading/data.ts)、[模式加载](../../../apps/readest-app/src/features/reading-modes/state.ts) 不读取副本；[主题保存](../../../apps/readest-app/src/features/reading-modes/thematic.ts) 直接覆盖唯一主文件。合成复现确认损坏主文件不会回退、主题连续保存也无副本。

**方案**：统一“数据校验 → 临时文件写入 → 替换 → 保留上一有效版本 → 损坏回退”。损坏原件应保留，恢复后明确显示恢复时间。可参考 [已有 persistence 工具](../../../apps/readest-app/src/services/persistence.ts)，但不能因其默认值行为而掩盖用户数据损坏。

**验收**：分别模拟 JSON 截断、非法结构、写入失败；能够恢复上一有效版本、不覆盖原损坏文件，并保留可理解的错误提示。

### F04｜当前回归套件不能代表当前产品

**证据**：CI [执行全部 Web e2e](../../../.github/workflows/pull-request.yml)，但 [旧主题测试](../../../apps/readest-app/e2e/tests/thematic-reading.spec.ts) 仍寻找已移除的五步界面。连 README 推荐的现行测试也有一处明确冲突：[测试断言](../../../apps/readest-app/e2e/tests/reader-integration.spec.ts) 要求“金色标记是回答引用的具体位置”，[当前实现](../../../apps/readest-app/src/features/reading-modes/ModeReader.tsx) 显示“金色标记会保留到翻页或手动关闭”。流程到达该断言会失败。

**方案**：迁移或归档旧流程测试，建立 Active Reader 独立的发布检查入口。优先断言“定位正确、标记出现、翻页清除、返回会话保留”，减少与非关键文案的耦合。

**验收**：干净环境跑完整当前流程并通过；CI 和本地使用同一入口，覆盖导入、三种模式、保存后重启、引用往返、停止与重试。**本次没有实际运行完整 e2e，不把静态发现写成 CI 已失败。**

### F05｜重试没有牢靠绑定所属主题

有两个确定性的触发分支：

- **无书籍依据的连续讨论**：非首轮追问失败后重试，[按钮](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx) 用“是否选了书”决定重新分析书库，[请求分支](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx) 因问题不同而创建新主题，历史上下文被重置。
- **主题 A 失败后切换到 B**：[历史切换](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx) 没有清除或重建 `retryQuery`。B 的“重新回答”仍可能发送 A 的问题。

**方案**：重试记录保存 `researchId`、用户消息 ID、原上下文和检索策略；只有明确的新主题动作可以创建主题。切换会话时从该会话自身恢复重试状态。

**验收**：模拟第二轮失败与跨主题切换；重试只作用于原问题、原主题，不丢历史、不生成重复用户消息，不新增意外主题。

### F06｜普通对话没有完整的消息状态

**触发与影响**：流式输出一半后停止或断网。[异常分支](../../../apps/readest-app/src/features/reading-modes/DialogueCard.tsx) 把部分回答存为普通 assistant 消息，而 [消息类型](../../../apps/readest-app/src/features/reading-modes/DialogueCard.tsx) 没有状态字段。后续 [历史过滤器](../../../apps/readest-app/src/features/reading-modes/conversation.ts) 只能过滤已标记 `error/stopped` 的消息，因此不完整内容继续进入模型上下文。

**方案**：统一普通对话与主题消息的 `streaming/complete/stopped/error` 状态；中断标记绑定到具体消息。普通追问默认排除中断回答，明确“继续生成”时才携带该片段。

**验收**：输出部分文本后分别停止、断网，再普通追问/继续生成，四条路径的模型输入与界面状态符合预期。

### F07｜保存失败缺少可执行的恢复动作

**触发与影响**：模型回答成功但最后写文件失败。[persist](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx) 捕获错误，提示“请重试”，但不返回失败；[后续逻辑](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx) 仍清空重试问题。用户无法直接重试保存，离开或重启可能丢失内存中的回答。

**方案**：保存函数返回明确结果；保留待保存快照，显示“重新保存”。本地写入重试与 AI 重新生成分开处理。

**验收**：注入一次落盘失败后，点击“重新保存”只写本地数据，不重新调用模型；成功后重启可见原回答。当前为代码确认，尚未做 UI 写盘故障注入。

### F08｜来源检查的覆盖范围需要统一并如实显示

**事实**：主题阅读已有编号引用核对、无效编号处理和失败提示。但 [普通对话请求完成](../../../apps/readest-app/src/features/reading-modes/DialogueCard.tsx) 后直接加入回答；主题核对也只针对 [编号引用](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx)，[核对函数输入](../../../apps/readest-app/src/features/reading-modes/research-assistant.ts) 不含公开网页来源。

**影响**：用户容易把“找到了资料”“有引用”“核对已完成”理解成同一件事；README 对普通对话与主题回答的概括也应更准确。

**方案**：为每条回答区分原文、个人笔记、公开网页和模型分析，显示实际核对范围；选文与网页摘要逐步进入统一来源映射。先保证状态真实，再扩展核对。模型核对本身仍不能等同事实保证。

**验收**：对错误作者归因、不存在的引用 URL、摘要不支持结论等固定样例，能纠正或显示未核对；正确书籍引用继续可回跳。

### F09｜正文右下操作按钮实际重叠

**实测**：桌面 1224×768 窗口，显示阅读工具栏后，“笔记与疑问 · 5”遮挡“呼叫小墨”左侧，见截图 E03。

**根因**：[两个同级按钮](../../../apps/readest-app/src/features/reading-modes/ModeReader.tsx) 使用 [绝对定位](../../../apps/readest-app/src/features/reading-modes/modes.css)，右侧偏移分别为 35px、155px，只给右侧按钮留出 120px，容纳不了其图标、文字、快捷键和内边距。

**方案**：放入同一个布局容器，用 `flex` 和 `gap` 排列，按当前阅读窗格宽度适配。

**验收**：1224×768、1440×900、360px 宽、150% 缩放、并排阅读，以及记录数 0/5/99+ 时均不重叠、完整可点击。

### F10｜主题检索的取消与规模适应性不足

**机制**：[索引循环](../../../apps/readest-app/src/features/reading-modes/thematic-passages.ts) 只在书与书之间检查取消；单本书的哈希、解析与章节抽取没有传递 signal。即使命中缓存，也先 [完整计算文件 MD5](../../../apps/readest-app/src/features/reading-modes/thematic-passages.ts)。工作区 [建立索引](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx) 涉及整个可用书库。

**影响**：停止要等当前书处理结束；书库扩大后，热检索仍可能承担明显的全量读取与计算开销。当前不能据此声称“1000 本一定卡顿”，实际耗时与内存仍需测量。

**方案**：signal 贯穿读取与章节循环；分块让出主线程；限制并发；建立可失效的版本缓存、增量索引和按需加载。先量测，再决定是否需要 Worker 或本地数据库索引，不急于引入向量服务。

**验收建议**：10/100/1000 本分别测冷/热索引 p50/p95、峰值内存、长任务和取消延迟。建议停止后 300ms 内反馈、1 秒内恢复输入；100 本热检索 p95 先以 2 秒为目标，按目标设备校准。这里不包含模型网络时间。

### F11｜主题弹窗的键盘操作还不完整

**代码证据**：[历史主题](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx)、[引用来源](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx)、[调整书目](../../../apps/readest-app/src/features/reading-modes/ThematicWorkspace.tsx) 使用普通 section 加 `role=dialog`、`aria-modal=true`，缺少焦点圈定、背景 inert、关闭后的焦点恢复；调整书目还没有初始聚焦。已有 Escape 关闭，不能据此认为完整键盘体验已经覆盖。

**方案**：复用项目已有 Dialog 基础组件，统一初始焦点、Tab 循环、Escape 和返回焦点。截图 E05 记录了本次实际弹层；截图本身不能证明读屏结果。

**验收**：纯键盘打开书目、选择、完成；打开引用、关闭；焦点始终处于正确区域，返回触发按钮。补一次 VoiceOver 实测，不以截图替代无障碍检查。

| 方向 | 建议的最小版本 | 用户价值 | 验收方式 |

| 首次连接小墨更清楚 | 在现有设置上增加简短连接引导；选择服务、填写连接、测试、完成；实验性 Reedy 选项放到高级区 | 当前界面同时出现 Ollama、模型网关、OpenAI 兼容与实验项，新用户需要理解较多技术词（E04） | 找 3–5 位未用过软件的人，不口头指导完成连接；记录卡点与完成时间 |
| 从书库直接继续思考 | 提供最近主题、未解决疑问、继续阅读的轻量入口；主题可直接恢复原会话 | 减少为了继续跨书研究而先进入某一本书的绕行 | 从书库两步内回到上次主题或待处理疑问，书籍定位仍保留 |

| 检索范围和状态可理解 | 回答附近保留本轮使用的书目/网页状态，区分本地检索、回答、引用核对、保存 | 等待时知道正在做什么，遇到错误知道该重试哪一步 | 模拟检索失败、模型失败、核对失败、保存失败，出现各自有效动作 |

阅读时应保留现有正文优先、工具栏可收起的方向。新增入口适合放在书库、主题头部或侧栏，不宜让读书页持续堆叠卡片和按钮。
